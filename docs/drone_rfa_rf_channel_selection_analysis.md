# DroneRFa 射频通道选择分析

## 1. 结论

项目现已按 DroneRFa 文件中 `S` 编码选择单个 RF 通道，不再将 `RF0` 和 `RF1` 作为同一个样本的两个互补特征通道。

结合论文中的信号片段编码和采集设备配置，建议按文件名选择目标接收通道：

| 信号片段编码 | 工作频段含义 | 应读取的 IQ 数据 |
| --- | --- | --- |
| `S0000-S0111` | 初始通信频段，即 915 MHz 或 2.4 GHz | `RF0_I + j * RF0_Q` |
| `S1000-S1111` | 若设备支持，切换至 2.4 GHz 或 5.8 GHz | `RF1_I + j * RF1_Q` |

因此，后续 STFT 和 CPP/FAM 特征应由所选的单路复数 IQ 信号生成，而不是同时处理 `RF0` 和 `RF1`。

## 2. 论文依据

依据 `docs/DroneRFa：用于侦测低空无人机的大规模无人机射频信号数据集.pdf`：

- 第 1149 页表 3 说明：
  - `S0000-S0111` 表示“设置初始通信在 915 MHz 或 2.4 GHz”；
  - `S1000-S1111` 表示“若设备支持则切换至 2.4 GHz 或 5.8 GHz”。
- 第 1150 页采集流程说明：
  - 默认情况下，`RF0` 的中心频率为 2440 MHz；
  - 默认情况下，`RF1` 的中心频率为 5800 MHz；
  - 对仅支持 915 MHz 和 2.4 GHz 的特定设备，`RF0` 设置为 915 MHz，`RF1` 设置为 2440 MHz。

论文明确给出了 `S` 编码的频段含义以及两个接收通道的中心频率，但没有直接写出“按 `S` 编码丢弃另一通道”。上述选择规则是根据这两项采集定义得到的推论。

论文的 ResNet-18 实验将输入尺寸写为 `(2, 1024, 1024)`，但正文没有进一步解释两个输入通道的具体构造。因此，论文中的双通道实验设置不能消除当前项目在目标信号选择上的语义问题。

## 3. 改造前实现的问题

### 3.1 原始 IQ 读取

`src/data/drone_rfa_io.py` 中的 `read_iq_batch()` 无条件读取 `RF0_I/Q` 和 `RF1_I/Q`，并返回形状为 `(B, 2, L)` 的复数数组。函数没有解析文件名中的 `S` 编码，也没有选择目标频段。

此外，`count_iq_samples()` 固定使用 `RF0_I` 的长度计算样本数。改为按文件选择通道后，样本计数也应基于被选中的通道。

### 3.2 STFT 特征

`scripts/precompute_stft_h5.py` 将 HDF5 特征固定保存为 `(N, 2, H, W)`，`src/preprocess/stft.py` 则分别计算两路 IQ 的 STFT，并对每路频谱独立执行 z-score 归一化。

这会使非目标频段中的环境信号或噪声成为模型输入。由于每路独立归一化，即使非目标通道幅度很低，其噪声结构也会被放大到与目标通道相近的数值尺度。

### 3.3 CPP/FAM 特征

`scripts/precompute_cpp_h5.py` 分别取出 `RF0` 和 `RF1`，对两路信号独立执行 RF 片段选择和 FAM 计算，最后由 `src/preprocess/cpp.py` 将两个结果堆叠为 `(2, H, W)`。

每路 FAM 网格在堆叠前都会按自身最大值归一化，随后 CPP 又按通道执行归一化。因此，非目标通道中的噪声循环平稳结构可能被显著放大。同时，对非目标通道执行完整 FAM 计算也带来了接近一倍的无效计算量。

### 3.4 模型和可视化

`src/models/resnet.py` 将 ResNet-18 的第一层固定为两个输入通道，并明确把它们定义为 `RF0` 和 `RF1`。现有模型可能利用“哪一路更活跃”判断频段或 `S` 分组，而不是只学习无人机信号本身的特征。

STFT 和 CPP 的 PNG 生成脚本也固定绘制两个通道，需要随特征格式一起调整为单通道展示。

## 4. 对低信噪比实验的影响

改造前的双通道输入会影响合成 SNR 的物理含义。

训练预计算和原始 IQ 评估中的 AWGN 实现都按两个通道的联合平均功率计算噪声功率。若目标通道功率为 `P`，非目标通道功率近似为零，则联合平均功率约为 `P / 2`。按该功率生成噪声后，目标通道的实际 SNR 将比配置值高约：

```text
10 * log10(2) = 3.01 dB
```

如果非目标通道中还存在环境信号或其他通信活动，偏差会随文件变化，导致同一个配置 SNR 无法对应稳定的目标信号 SNR。

因此，现有训练结果和 SNR-准确率曲线不能严格解释为所选无人机信号在指定 SNR 下的识别能力。正确顺序应当是先选择目标 RF 通道，再根据该通道自身功率添加 AWGN。

## 5. 推荐数据流

建议统一使用以下处理流程：

```text
文件名
  -> 解析 S 编码
  -> S0000-S0111 选择 RF0，S1000-S1111 选择 RF1
  -> 读取单路复数 IQ，形状为 (B, 1, L)
  -> 根据所选信号功率添加目标 SNR AWGN
  -> 生成 STFT 或 CPP/FAM
  -> 保存单通道特征，形状为 (N, 1, H, W)
  -> 使用单通道 ResNet 训练和评估
```

通道选择应集中在原始数据读取层实现，预计算和 SNR 评估共用同一套文件名解析与读取逻辑，避免两条路径出现不同的数据语义。

## 6. 兼容性和实验处理

改为单通道特征后：

- 现有双通道 STFT 和 CPP HDF5 缓存不再兼容，需要重新生成；
- ResNet 第一层权重形状会从 `(64, 2, k, k)` 变为 `(64, 1, k, k)`，现有 checkpoint 不能直接作为等价模型继续使用；
- 模型需要重新训练，并重新计算干净数据和各 SNR 点的评估结果；
- 现有文件级 split manifest 可以继续复用，因为原始文件 ID 和类别标签没有变化；
- 默认缓存目录和 checkpoint 名称保持不变，但必须完整重新预计算和重新训练；加载器会拒绝残留的旧双通道 H5。

## 7. 研究范围边界

`S` 编码表示通信频段和信号片段序号，不表示文件一定只包含图传下行信号。无人机通信可能同时包含：

- 遥控器到无人机的上行跳频控制信号；
- 无人机到遥控器或手机的下行 OFDM 图传信号。

按 `S` 编码选择 RF 通道能够消除当前明显的频段混用问题，但不能自动完成“纯图传信号”筛选。如果研究目标严格限定为低信噪比图传信号识别，还需要进一步依据时频结构、设备能力或额外标注确认哪些片段实际包含图传信号。
